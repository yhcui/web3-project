# EVM Block Scanner 项目分析总结

## 📖 项目简介

这是一个 **EVM 区块链扫描器**（EVM Block Scanner），用于实时监控多条区块链上的交易活动，并将解析后的活动推送到 Gateway 网关。

**核心能力**：
- 🔍 同时扫描多条 EVM 兼容链（Ethereum、BSC、Polygon、Arbitrum、Base、Optimism 等）
- 🎯 智能过滤：使用 Bloom Filter 快速筛选目标地址的交易
- 📊 交易解析：识别 ERC20 转账、授权、Uniswap Swap 等
- 📜 历史回填：通过 Etherscan/Blockscout API 获取历史交易数据
- 💰 代币发现：使用 Multicall 批量查询用户的代币余额
- 🔗 Reorg 检测：自动处理区块链重组（分叉）
- 📡 Gateway 推送：将活动实时推送到 WebSocket 网关

  ├── 启动健康检查（定期检测 RPC 节点是否可用）
  ├── 启动 HTTP 服务（/approval-list、/parse-transactions、/ws/tx-status）

  ├── 启动统计信息定时输出（每分钟）
  └── 启动所有 Scanner（开始扫描区块）
```

### 2. 区块扫描流程

```
Scanner.Start()
  │
  ├── Client.Subscribe()  ← 订阅新区块
  │     ├── WebSocket: newHeads 订阅
  │     ├── 或 HTTP 轮询: eth_blockNumber
  │     ├── 定期高度检查（防止遗漏）
  │     └── 定期清理旧的已处理区块记录
  │
  ├── 收到新区块通知
  │     │
  │     ├── 第一层过滤：from/to 地址快速匹配（零开销）
  │     │     └── 直接匹配订阅地址
  │     │
  │     ├── 第二层过滤：Bloom Filter 预判
  │     │     └── 使用 Receipt 的 Bloom 过滤器快速排除不相关的交易
  │     │
  │     └── 并发解析候选交易
  │           ├── parse.Parse() 解析每笔交易
  │           ├── 第三层过滤：精确匹配（消除 Bloom 假阳性）
  │           └── 将解析结果发送到 channel
  │
  └── App 的消费协程
        ├── 从 channel 接收解析后的交易
        └── 分发给所有注册的 Handler（如 Gateway Handler）
```

### 3. 交易解析流程

```
parse.Parse()
  │
  ├── 获取交易 Receipt（如果未预取）
  ├── 计算 Gas 价格（优先用 Receipt 中的实际成交价）
  ├── 计算交易费用（gasUsed × gasPrice）
  ├── 格式化金额（Wei → ETH）
  │
  ├── 遍历已注册的 Parser（按优先级排序）
  │     ├── Uniswap v4（优先级 100）：匹配 Swap 路由合约
  │     ├── ERC20（优先级 0）：匹配 transfer 方法
  │     ├── BEP20（优先级 0）：BSC 链的 ERC20
  │     └── Unknown（优先级 -100）：兜底解析
  │
  ├── 匹配的 Parser 处理交易
  │     ├── 解析事件日志（Transfer/Approval/Swap等）
  │     ├── 解析内部交易（可选，需要 trace API）
  │     └── 设置 Summary（如 SwapSummary）
  │
  └── 返回解析后的 Transaction 对象
```

### 4. 数据流转

```
区块链节点（RPC）
      │
      ▼
  Scanner（扫描+过滤）
      │
      ▼
  parse.Parse（解析交易）
      │
      ▼
  App.ch（channel）
      │
      ├── Gateway Handler

## 🔑 核心模块详解

### 1. Client（客户端模块）

**职责**：封装与区块链节点的 RPC 通信

**关键组件**：
- `Endpoint`：RPC 端点管理，支持多节点故障转移
- `Wrapped`：包装的 ethclient，带限流和健康检查
- `Client`：高层封装，提供区块订阅、交易监控等功能

**核心方法**：
- `Subscribe()`：订阅新区块（WebSocket 或 HTTP 轮询）
- `BlockByNumber()`：获取指定区块
- `TransactionReceipt()`：获取交易回执
- `FilterLogs()`：查询事件日志

**特色设计**：
- 连接池模式，自动故障转移
- 每个节点独立限流（RPS）
- 定期健康检查，自动恢复

### 2. Scanner（扫描器模块）

**职责**：扫描区块，过滤和解析交易

**三层过滤机制**：
1. **第一层**：from/to 地址快速匹配（O(1)）
2. **第二层**：Bloom Filter 预判（O(n)，但很快）
3. **第三层**：精确匹配解析后的交易（消除假阳性）

**并发模型**：
- 每个区块的交易并发解析（goroutine）
- 使用 WaitGroup 等待所有交易处理完成
- 使用 atomic 统计匹配/成功/失败数量

### 3. Parse（解析器模块）

**职责**：解析交易，识别协议类型

**设计模式**：策略模式 + 优先级

**Parser 接口**：
```go
type Parser interface {
    Match(tx *Transaction) bool  // 是否匹配
    Priority() int                // 优先级（越大越先）
    String() string               // 协议名称
    Handler(tx *Transaction) error // 处理逻辑
}
```

**LogParser 接口**（可选）：
```go
type LogParser interface {
    ParseLog(tx *Transaction, vLog *types.Log) any
}
```

**已实现的 Parser**：
- `UniSwapv4`：优先级 100，识别 Uniswap Swap
- `ERC20`：优先级 0，识别 ERC20 转账/授权
- `BEP20`：优先级 0，BSC 链的 ERC20
- `Unknown`：优先级 -100，兜底解析

### 4. Storage（存储模块）

**职责**：持久化存储区块队列、高度映射、回填进度

**使用的数据库**：
- **SQLite**：区块队列、回填游标（支持复杂查询）
- **bbolt**：区块高度映射（简单 KV，性能更高）

**BlockQueue（区块队列）**：
- 支持优先级（新区块优先于追块）
- 支持失败重试（指数退避）
- 支持 Reorg 检测（parentHash 链式校验）
- 使用事务保证原子性

**HeightMap（高度映射）**：
- 使用 bbolt KV 数据库
- 存储每条链的最新区块高度
- 小端序二进制编码 uint64

### 5. Gateway（网关模块）

**职责**：与 Gateway 网关建立 WebSocket 连接

**消息类型**：
- `register`：注册扫描器
- `subscribe/unsubscribe`：订阅/取消订阅地址
- `sync`：全量同步订阅地址
- `activity`：推送交易活动
- `backfill`：历史回填任务
- `token_discovery`：代币发现任务
- `ping/pong`：心跳

**Handler 机制**：
- 将解析后的交易标准化为 `StandardActivity`
- 通过 WebSocket 推送到 Gateway
- 支持按订阅地址过滤

## 🔧 技术亮点

### 1. 三层过滤机制

**问题**：区块中可能有几百笔交易，但只有少数与订阅地址相关

**解决方案**：
1. **第一层**：from/to 地址匹配（O(1)，最快）
2. **第二层**：Bloom Filter 预判（O(n)，但 Bloom Filter 查询很快）
3. **第三层**：精确匹配解析后的交易（消除 Bloom 假阳性）

**效果**：大幅减少不必要的交易解析，提升性能

### 2. Bloom Filter 优化

**原理**：Bloom Filter 是一种概率数据结构，可以快速判断元素是否**可能**在集合中

**应用**：
- Receipt 中包含 Bloom Filter，记录了所有事件涉及的地址
- 先检查订阅地址是否**可能**在 Receipt 中
- 如果 Bloom Filter 说"不在"，则 100% 确定不在（跳过）
- 如果 Bloom Filter 说"在"，则**可能**在（需要进一步验证）

**优点**：快速排除大量不相关的交易

### 3. Multicall 批量查询

**问题**：查询 100 个代币的余额需要 100 次 RPC 调用

**解决方案**：使用 Multicall3 合约，一次调用查询多个代币余额

**原理**：
- Multicall3 是一个部署在所有 EVM 链上的合约
- 接受多个调用请求，批量执行并返回结果
- 将 100 次 RPC 调用减少到 1 次

**效果**：大幅提升代币发现性能

### 4. Reorg 检测

**问题**：区块链可能发生分叉，导致之前处理的区块失效

**解决方案**：
- 保存每个已处理区块的哈希和父哈希
- 处理新区块时，验证 parentHash 是否匹配
- 如果不匹配，说明发生了 Reorg，需要回滚

**回滚逻辑**：
1. 找到分叉点（最近的匹配区块）
2. 删除分叉点之后的所有已处理记录
3. 将这些区块重新加入队列（高优先级）

### 5. Singleflight 防穿透

**问题**：多个协程同时请求同一个代币信息，导致重复 RPC 调用

**解决方案**：使用 `golang.org/x/sync/singleflight`

**原理**：
- 对同一个 key（代币地址），只允许一个请求在执行
- 其他请求等待这个请求完成，共享结果
- 避免"缓存击穿"问题

### 6. 连接池 + 故障转移

**问题**：单个 RPC 节点可能不可用或限流

**解决方案**：
- 配置多个 RPC 节点（WebSocket + HTTP）
- 使用连接池管理所有节点
- 调用失败时自动切换到下一个节点
- 定期健康检查，自动恢复

## 🎯 配置说明

### 基本配置

```yaml
# 服务器地址
server_address: ":7788"

# Etherscan API（用于历史回填）
etherscan_api_key: "YOUR_API_KEY"
etherscan_api_prs: 2  # 每秒请求数

# 重启时是否跳过追块
skip_catch_up: true  # true=直接从最新区块开始，false=追块
```

### 端点配置

```yaml
endpoints:
  - name: "Ethereum"           # 链名称
    chain: "eth"               # 链标识
    interval: 5000             # 轮询间隔（毫秒）
    max_workers: 10            # 并发处理区块的 worker 数量
    discovery_workers: 32      # 代币发现的并发数
    multicall_batch_size: 1000 # Multicall 批量大小
    urls:
      - url: "wss://..."       # WebSocket URL
        prs: 100               # 每秒请求数限制
      - url: "https://..."     # HTTP URL（备用）
        prs: 50
```

### Gateway 配置

```yaml
gateway:
  enabled: true                          # 是否启用
  url: "ws://localhost:9000/ws/upstream" # Gateway WebSocket 地址
  reconnect_interval_ms: 5000            # 重连间隔
  ping_interval_ms: 30000                # 心跳间隔
```

### 历史回退配置

```yaml
history_fallback:
  blockscout_prs: 2  # Blockscout 每秒请求数
  blockscout_hosts:
    "8453": "https://base.blockscout.com/api"  # Base 链的 Blockscout
```

## 💡 Go 语言核心概念速查

### Goroutine（协程）

```go
// 启动一个协程
go func() {
    // 并发执行的代码
}()
```

**概念**：轻量级线程，由 Go 运行时调度，可以同时执行多个任务

### Channel（通道）

```go
// 创建 channel
ch := make(chan int)

// 发送数据
ch <- 42

// 接收数据
value := <-ch
```

**概念**：协程之间通信的管道，遵循 CSP 并发模型

### Context（上下文）

```go
// 创建带取消的 context
ctx, cancel := context.WithCancel(context.Background())
defer cancel()

// 检查是否取消
select {
case <-ctx.Done():
    return
default:
    // 继续执行
}
```

**概念**：用于控制协程的生命周期，传递取消信号和截止时间

### Interface（接口）

```go
type Parser interface {
    Match(tx *Transaction) bool
    Handle(tx *Transaction) error
}

// 实现接口
type ERC20Parser struct{}

func (p ERC20Parser) Match(tx *Transaction) bool {
    return true
}

func (p ERC20Parser) Handle(tx *Transaction) error {
    return nil
}
```

**概念**：定义行为规范，实现多态和依赖注入

### Defer（延迟执行）

```go
func example() {
    file, _ := os.Open("file.txt")
    defer file.Close()  // 函数返回时执行
    
    // 使用 file...
}
```

**概念**：延迟执行函数，常用于资源清理（关闭文件、释放锁等）

### Error Handling（错误处理）

```go
result, err := doSomething()
if err != nil {
    return fmt.Errorf("do something failed: %w", err)
}
```

**概念**：Go 不使用异常，而是返回 error 值，显式处理错误
