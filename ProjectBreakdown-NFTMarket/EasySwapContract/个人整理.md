# NFT相关业务知识
## 集合（Collection）
定义：NFT集合是指一系列相关的非同质化代币（NFT）的合集，通常由同一个项目或创作者发行。每个集合有独特的智能合约地址，包含多个NFT（如10000个）。

重要性：集合是NFT市场的基本单位，地板价、交易量等指标都基于集合计算。热门集合往往有社区、稀有度（Traits）和实用价值（Utility）。

## 地板价（Floor Price）
定义：一个NFT集合中，目前挂单（上市出售）的最低价格。它代表了进入这个集合的最低成本（不包括买家的出价）。

如何计算：平台（如OpenSea或Blur）直接取集合中所有挂单NFT的最低价格作为地板价。如果有人买走了最低价的NFT，地板价就会自动上升到下一个最低挂单价。

相关行为：地板价高表示集合受欢迎；低地板价可能意味着需求弱或项目冷门。

## 卖单（Listing / Ask / Offer to Sell）

定义：卖家将自己的NFT挂在市场上出售的订单，指定一个固定价格（或拍卖形式）。也叫“挂单”或“Ask”（卖方报价）。

与地板价关系：所有卖单中的最低价决定了地板价。

## 买单（Bid / Offer）

定义：买家对某个NFT（或整个集合）提出的出价，表示“我愿意出这个价买”。也叫“Offer”或“Bid”（买方报价）。

区别于卖单：买单通常低于卖单（低球出价常见），地板价不包括买单，只看卖单。

## 扫地板（Sweep the Floor）：

大户或交易者一次性买入多个（甚至所有）地板价附近的NFT，迅速推高地板价。常见于Blur平台，支持批量扫单（Sweep）。

目的：看好项目上涨，提前低价囤货，或操纵价格吸引关注。

风险：如果项目不火，容易亏损。

## 稀有度（Rarity / Traits）：

集合中每个NFT有不同属性（如背景、衣服），稀有属性让某些NFT价值远高于地板价（叫“Rare NFT”）。

## 出价墙 / 买单墙（Bid Wall）：

大量买单堆积在某个价格附近，形成支撑，防止地板价下跌。

## 翻转（Flip）：
低价买入（常在地板价），快速高价卖出赚钱。

## 皇室费（Royalties）：
创作者在每次二手交易中抽成的百分比（通常5-10%），部分平台可选择性支付。

## 一个集合是否属于一个合约？
大多数情况下是一个集合对应一个智能合约。如ERC721代币，一个集合对应一个合约。
有些项目用ERC-1155（半同质化）一个合约管理多个子集合。
极少数项目会用多个合约（比如升级或分批发行），但这会让集合显得“分散”，不利于统一管理和地板价显示。

## 一个合约是否属于一个人或团体？
不完全属于。合约部署后，控制权有限，且NFT所有权是分散的。

## 我自己写合约，自己铸造NFT，自已卖不就可以了么。现实不是这样的么？
你说的这种模式确实存在，而且非常常见——很多NFT项目早期就是这么玩的：
- 项目方自己写合约
- 自己部署
- 自己铸造（Mint）所有或大部分NFT
- 自己决定什么时候、怎么卖、卖给谁
但关键在于：一旦你把NFT卖出去（或公开铸造给别人），所有权就彻底转移了，你就失去了对这些NFT的控制。这才是“现实不是那样的”核心原因。

你完全可控的阶段（前期）

- 合约编写和部署阶段

- 铸造和初始销售阶段
    你可以选择：
    - 自己把所有NFT都Mint到自己钱包（100%控制）
    - 只公开卖一部分，剩下自己持有
    - 直接公开免费/低价铸造（Free Mint或固定价Mint）
    - 这个阶段你确实可以“自己卖，自己定价格”，甚至可以先不上市，只在自己手里捂着。

失去控制的转折点：NFT进入二级市场  
一旦你做了以下任何一件事，控制权就开始流失：  
你把NFT卖给了别人（不管是公开Mint还是私下交易）  
别人在OpenSea、Blur等平台上挂单出售  
持有者开始自由交易  

# 主要业务流程 
## 资产存管：  

- 挂单 (List)：卖家创建订单时，NFT 会直接转入 EasySwapVault 进行托管。

- 报价 (Bid)：买家创建订单时，需要存入相应数额的 ETH 到 Vault。

##  撮合机制：

- 支持单笔撮合和批量撮合 (matchOrders)。

- 在批量撮合中，系统使用 delegatecall 内部调用撮合逻辑，以实现原子性操作：要么全部（或部分指定）成功，要么回滚。

## 订单编辑
用户可以在不取消原订单的情况下修改价格，系统会自动计算差价并进行多退少补。


# maker和taker分别代表什么
Maker 和 Taker 是交易的两个对立方，分别代表“订单的创建者”和“订单的执行者”。

## Maker (挂单者 / 创建者)
Maker 是指在市场上“制造”流动性的人。他主动发布一个买单或卖单，并等待别人来成交。  
在代码中的体现：在 LibOrder.sol 的 Order 结构体中，有一个专门的字段 address maker，记录的就是发布这笔订单的人。  
具体行为：  
- 卖方 Maker：调用 makeOrders 函数，将自己的 NFT 存入 Vault（金库），挂出一个价格（Side = List）。
- 买方 Maker：调用 makeOrders 函数，将 ETH 存入 Vault，挂出一个求购价格（Side = Bid）。  
特点：Maker 的资金或 NFT 会在订单成交前被锁定在合约（EasySwapVault）中。


## Taker (吃单者 / 匹配者)
Taker 是指“取走”流动性的人。他看到了 Maker 挂出的订单，觉得价格合适，于是决定接受这个价格并立即完成交易。  
在代码中的体现：Taker 通常是调用 EasySwapOrderBook.sol 中 matchOrder 或 matchOrders 函数的人（即 msg.sender）。  
具体行为：  
- 如果 Maker 挂的是卖单（NFT），Taker 就是买家。Taker 支付 ETH，瞬间拿走 Maker 锁在金库里的 NFT。  
- 如果 Maker 挂的是买单（ETH），Taker 就是卖家。Taker 提供 NFT，瞬间拿走 Maker 锁在金库里的 ETH。  
特点：Taker 不需要提前挂单，他的操作通常是“即时成交”的。  

# taker可以创建order么，还是只能maker创建？

1. Maker 创建的是“持久化订单”
当你调用 makeOrders 函数时，你就是 Maker。

动作：你创建了一个订单并将其存入了 OrderStorage（红黑树和队列中）。

状态：这个订单会一直挂在链上，直到被别人匹配（Match）、被你自己取消（Cancel）或过期（Expiry）。

结论：只有 Maker 才能在订单簿中留下“足迹”。

2. Taker 创建的是“即时匹配订单”
当你看到别人挂好的单子，想去成交它时，你就是 Taker。

动作：你会调用 matchOrder 或 matchOrders 函数。

逻辑细节：有趣的是，在调用 matchOrder 时，Taker 也需要传入一个 Order 结构体（作为参数）。

但是，这个订单不会被存入红黑树存储层。

它只是作为一个“对手方证明”，用来和存储层里已有的 Maker 订单进行逻辑比对（价格、资产是否匹配）。

结论：Taker 在操作时也“构建”了订单数据，但它不是为了“挂单”，而是为了“吃单”，操作完即焚，不占存储。

3. Taker 可以转变为 Maker 吗？
当然可以。 * 如果你想买一个 NFT，但现在市场上没人在卖（或者价格太贵），你不想直接调用 matchOrder（当 Taker），你可以选择调用 makeOrders 挂一个低价买单（Bid）。
