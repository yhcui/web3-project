# 项目概述
EasySwapSync 是一个 NFT 订单簿索引器服务，用于监听和同步区块链上的 NFT 交易事件。
该项目主要功能是实时监控智能合约上的订单创建、取消和匹配事件，并将这些数据同步到数据库中。
# 核心业务逻辑
## 订单簿事件同步
事件监听: 通过以太坊客户端监听智能合约事件  
事件类型:  
- LogMakeTopic - 挂单事件（创建订单）
- LogCancelTopic - 取消订单事件
- LogMatchTopic - 匹配成交事件

##  事件处理逻辑
### 挂单事件处理 (handleMakeEvent)
- 解析链上日志数据，提取订单信息
- 存储订单到 Order 表
- 记录活动到 Activity 表
- 添加到订单管理队列

### 匹配事件处理 (handleMatchEvent)
- 处理买卖双方订单匹配成交
- 更新订单状态为已成交
- 更新 NFT 所有者信息
- 记录销售活动
- 添加价格更新事件

### 取消事件处理 (handleCancelEvent)
- 更新订单状态为已取消
- 记录取消活动
- 添加价格更新事件

# 主要数据表
ob_activity_sepolia - 记录 NFT 活动（买卖、挂单、取消等）  
ob_order_sepolia - 存储订单信息  
ob_item_sepolia - NFT 项目信息  
ob_collection_sepolia - NFT 集合信息  
ob_collection_floor_price_sepolia - 集合地板价信息  
ob_indexed_status - 区块同步状态

# 集合地板价管理
- 定期更新: 每 150 秒查询一次集合地板价
- 计算逻辑: 查询每个集合中活跃的最低价格订单
- 数据清理: 定期删除过期的地板价数据（超过 2 个月）
- 持久化: 将地板价数据存储到数据库 
# 同步机制
##   区块同步循环 (SyncOrderBookEventLoop)
- 从上次同步的区块开始，批量获取区块日志
- 支持多链配置，不同链有不同的区块差异容忍度
-  持续监控新区块，实时处理新事件
##   配置参数
- SleepInterval: 10秒轮询间隔
- SyncBlockPeriod: 每次同步10个区块
- MultiChainMaxBlockDifference: 不同链的最大区块差异
# 订单类型管理
- ListingOrder: 卖单
- CollectionBidOrder: 集合买单
- ItemBidOrder: 单项 NFT 买单
- 订单状态: 活跃、已成交、已取消
#  服务启动流程
  加载配置文件
  初始化数据库连接
  初始化 Redis 连接
  创建链客户端
  预加载集合到过滤器
  启动订单簿索引服务
  启动订单管理器

# 业务场景
## 地板价
1. NFT市场展示
   集合页面：显示每个NFT集合的当前地板价
   市场概览：提供实时的市场数据和价格趋势
2. API接口服务
   为前端提供地板价查询接口
   支持第三方应用集成和数据展示
3. 价格监控与分析
   价格变化追踪：监控地板价的实时变化
   市场趋势分析：基于历史地板价数据进行分析
4. 交易决策支持
   定价参考：帮助卖家合理定价
   投资决策：为买家提供市场参考数据

  在NFT领域，地板价（Floor Price） 是指一个NFT系列（集合）中，当前市场上最低的挂单价格（即卖家愿意出售的最低价）。它直接来源于卖家的挂单订单（listings），而不是成交价或平均价。
地板价与订单的核心关系

地板价完全由卖方订单决定：
NFT市场（如OpenSea、Blur、Magic Eden）类似于一个订单簿（order book） 系统：卖家创建挂单（list for sale），指定价格和具体NFT。
- 平台实时扫描该系列的所有有效挂单，取其中最低的价格作为地板价。
- 示例：如果一个系列有挂单价格分别为0.1 ETH、0.2 ETH、0.3 ETH，则地板价就是0.1 ETH（最低挂单）。
- 如果有人买入这个0.1 ETH的NFT，地板价会自动上升到下一个最低挂单（0.2 ETH）。
- 如果有人新挂一个更低的单（如0.05 ETH），地板价立刻下降到0.05 ETH。

- 买方订单（bids/offers）不直接影响地板价：
- 买家可以出价（bid），但这些是“求购订单”，只有当卖家接受或匹配时才会成交。
- 地板价只看“卖单”（asks），不看“买单”（bids）。不过，高买单可能刺激卖家降低挂单，从而间接影响地板价。

## 业务场景
关于NFT买后卖单的业务模式
1. NFT批量操作支持
   代码逻辑支持在一次操作中完成买入并立即挂卖单
   通过 Buy 事件触发所有权转移
   同时查询新所有者（event.To）可能存在的挂单
2. 业务场景分析
   套利交易：用户可能以较低价格买入NFT，同时设定较高的卖出价格
   自动化策略：批量买卖操作，提高交易效率
   快速转售：买入后立即设置出售价格 
3. 操作模式对比
   单次操作：通过智能合约或批量交易实现买后立即挂单
   分步操作：传统方式需两次独立交易完成
   原子性保障：批量操作通常具有原子性，要么全部成功，要么全部失
